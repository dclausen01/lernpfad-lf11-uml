## 1. Wozu UML?

In einem Softwareprojekt reden viele Menschen miteinander: Kund:innen, Entwickler:innen, Tester:innen, die
Projektleitung. Damit alle dasselbe meinen, braucht es eine gemeinsame Sprache. Die **Unified Modeling Language
(UML)** ist so eine Sprache – allerdings eine grafische. Sie hilft dir, Software zu

- **spezifizieren** (Was soll das System können?),
- **visualisieren** (Wie ist es aufgebaut, wie läuft etwas ab?),
- **konstruieren** (Aus dem Klassendiagramm wird Code.) und
- **dokumentieren** (Wie funktioniert das System, das wir gebaut haben?).

UML ist **keine Programmiersprache** und an keine Programmiersprache gebunden. Sie passt aber besonders gut zur
objektorientierten Programmierung (Java, C#, Python …).

:::notiz Ein bisschen Geschichte
Anfang der 1990er-Jahre gab es viele konkurrierende Notationen. Grady Booch, Ivar Jacobson und James Rumbaugh
– die „drei Amigos“ – haben sie zusammengeführt. 1997 hat die **Object Management Group (OMG)** UML als Standard
übernommen. Die aktuelle Fassung ist **UML 2.5.1** (2017).
:::

## 2. Struktur oder Verhalten?

UML kennt **14 Diagrammtypen**. Sie teilen sich in zwei große Gruppen:

| | Strukturdiagramme | Verhaltensdiagramme |
| --- | --- | --- |
| Frage | Woraus besteht das System? | Was tut das System, wie läuft etwas ab? |
| Sicht | statisch – eine Momentaufnahme | dynamisch – verändert sich über die Zeit |
| Beispiele | Klassen-, Objekt-, Komponenten-, Verteilungsdiagramm | Anwendungsfall-, Aktivitäts-, Zustands-, Sequenzdiagramm |

Die **Interaktionsdiagramme** sind eine Untergruppe der Verhaltensdiagramme. Sie zeigen, wie Objekte miteinander
Nachrichten austauschen. Das wichtigste davon ist das Sequenzdiagramm.

## 3. Was kommt in der AP2 dran?

Im Prüfungsbereich **„Planen eines Softwareproduktes“** (90 Minuten) musst du UML-Diagramme lesen, ergänzen,
korrigieren und selbst erstellen. Im Themenkatalog werden diese sieben Diagramme genannt:

| Diagramm | Beantwortet die Frage | Modul |
| --- | --- | --- |
| Klassendiagramm | Welche Klassen gibt es, wie hängen sie zusammen? | [S1](modul:s1), [S2](modul:s2), [S3](modul:s3) |
| Komponentendiagramm | Aus welchen Softwarebausteinen besteht das System, über welche Schnittstellen reden sie? | [S5](modul:s5) |
| Verteilungsdiagramm | Welche Software läuft auf welcher Hardware? | [S5](modul:s5) |
| Anwendungsfalldiagramm | Wer nutzt das System wofür? | [V1](modul:v1) |
| Aktivitätsdiagramm | Wie läuft ein Prozess oder Algorithmus Schritt für Schritt ab? | [V2](modul:v2) |
| Sequenzdiagramm | Welche Objekte schicken sich in welcher Reihenfolge Nachrichten? | [V3](modul:v3) |
| Zustandsdiagramm | Welche Zustände kann ein Objekt haben, und was löst einen Wechsel aus? | [V4](modul:v4) |

Das **Objektdiagramm** ([S4](modul:s4)) steht nicht ausdrücklich im Katalog. Es hilft dir aber sehr, das
Klassendiagramm zu verstehen – deshalb ist es trotzdem dabei.

:::tipp So arbeiten die Prüfungsaufgaben
Typisch sind Aufgaben wie: „Ergänzen Sie das Klassendiagramm um …“, „Erstellen Sie aus dem Quelltext ein
Sequenzdiagramm“, „Welche Fehler enthält das Anwendungsfalldiagramm?“ oder „Modellieren Sie die Zustände eines
Auftrags“. Fast immer bekommst du dazu eine **Situationsbeschreibung**. Die wichtigste Fähigkeit ist also:
Text lesen und die passenden Elemente herausziehen.
:::

:::achtung Häufiger Irrtum
Das **ER-Diagramm** (Entity-Relationship-Modell) für Datenbanken gehört **nicht** zur UML. Es sieht dem
Klassendiagramm ähnlich, hat aber eine eigene Notation (z. B. Krähenfuß). Verwechsle die beiden in der Prüfung nicht.
:::

:::aufgabe basis 5 1 · Ordne zu
Ordne die Diagramme der richtigen Gruppe zu: Anwendungsfalldiagramm, Klassendiagramm, Zustandsdiagramm,
Komponentendiagramm, Sequenzdiagramm, Verteilungsdiagramm, Aktivitätsdiagramm, Objektdiagramm.

:::loesung
- **Strukturdiagramme:** Klassen-, Komponenten-, Verteilungs-, Objektdiagramm
- **Verhaltensdiagramme:** Anwendungsfall-, Zustands-, Aktivitäts-, Sequenzdiagramm (das Sequenzdiagramm ist
  zusätzlich ein Interaktionsdiagramm)
:::
:::

:::aufgabe plus 5 2 · Welches Diagramm passt?
Welches Diagramm würdest du jeweils zeichnen?
1. Die Kundin möchte wissen, welche Funktionen die neue App für sie und für die Mitarbeitenden bietet.
2. Du sollst zeigen, auf welchen Servern der Webshop und die Datenbank laufen.
3. Eine Bestellung kann „offen“, „bezahlt“, „versendet“ oder „storniert“ sein.
4. Du willst zeigen, in welcher Reihenfolge die App, der Server und der Zahlungsdienst miteinander kommunizieren.

:::loesung
1. Anwendungsfalldiagramm
2. Verteilungsdiagramm
3. Zustandsdiagramm
4. Sequenzdiagramm
:::
:::
