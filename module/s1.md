## 1. Aufbau einer Klasse

Eine **Klasse** ist der Bauplan für Objekte. Im Klassendiagramm ist sie ein Rechteck mit drei Bereichen
(Abteilungen):

1. **Klassenname** – im Singular, mit großem Anfangsbuchstaben, fett und zentriert (`Kunde`, nicht `Kunden`).
2. **Attribute** – die Eigenschaften, die jedes Objekt hat.
3. **Methoden** (in UML: Operationen) – was die Objekte können.

:::screenshot material/s1-klasse-aufbau.svg
Klasse „Kunde“ mit Attributen und Methoden. Die gelben Notizen erklären die Schreibweise.
:::

Die Schreibweise ist immer gleich:

| Element | Schreibweise | Beispiel |
| --- | --- | --- |
| Attribut | `Sichtbarkeit name : Typ [= Startwert]` | `- name : String` |
| Methode | `Sichtbarkeit name(param : Typ, …) : Rückgabetyp` | `+ leiheAus(rad : Fahrrad) : Ausleihe` |
| Konstruktor | wie eine Methode, Name = Klassenname, ohne Rückgabetyp | `+ Kunde(name : String, email : String)` |

:::achtung Typischer Fehler: Java-Schreibweise
In Java steht der Typ **vor** dem Namen (`private String name;`). In UML steht er **dahinter**, mit Doppelpunkt
(`- name : String`). Wer in der Prüfung die Java-Reihenfolge ins Diagramm schreibt, verliert Punkte.
:::

## 2. Sichtbarkeiten

| Zeichen | Name | Wer darf zugreifen? |
| --- | --- | --- |
| `+` | public | alle |
| `-` | private | nur die Klasse selbst |
| `#` | protected | die Klasse und ihre Unterklassen |
| `~` | package | alle Klassen im selben Paket |

:::tipp Faustregel Kapselung
Attribute sind fast immer **private** (`-`), Methoden meist **public** (`+`). Von außen kommt man über Getter und
Setter an die Werte. Getter und Setter darfst du in Prüfungsdiagrammen weglassen, wenn die Aufgabe das erlaubt –
lies die Aufgabenstellung genau.
:::

## 3. Statisch, abstrakt, Interface, Aufzählung

- **static** (Klassenattribut, Klassenmethode): gehört zur Klasse, nicht zu einem einzelnen Objekt –
  **unterstrichen**. Beispiel: ein Zähler `anzahlKunden`, der für alle Objekte gleich ist.
- **abstrakte Klasse**: von ihr kann man keine Objekte erzeugen. Name **kursiv** oder mit `{abstract}`.
  Abstrakte Methoden (ohne Rumpf) stehen ebenfalls kursiv.
- **Interface** (Schnittstelle): nur Methodensignaturen, die eine Klasse umsetzen muss. Über dem Namen steht
  das Schlüsselwort `«interface»`.
- **Aufzählung** (Enum): feste Liste von Werten mit `«enumeration»` über dem Namen.

:::screenshot material/s1-abstrakt-interface.svg
Links: abstrakte Klasse „Fahrrad“ (kursiv) mit der Unterklasse „EBike“. Mitte: Interface „Zahlungsart“, das die Klasse „Kreditkarte“ realisiert (gestrichelte Linie, hohles Dreieck). Rechts: die Aufzählung „RadZustand“.
:::

:::achtung Kursiv oder unterstrichen?
**Kursiv = abstrakt. Unterstrichen = statisch.** Diese beiden werden in der Prüfung gern vertauscht. Auf Papier
ist kursiv schwer zu schreiben – dann schreibst du `{abstract}` hinter den Namen.
:::

## 4. Detailstufen

Nicht jedes Klassendiagramm zeigt alles. Je nach Zweck lässt man Teile weg:

:::screenshot material/s1-detailstufen.svg
Dieselbe Klasse „Station“ dreimal: nur der Name (für Übersichten), mit Attributen und Methoden ohne Typen (Analyse) und vollständig mit Sichtbarkeiten und Datentypen (Entwurf).
:::

In der Analyse geht es um Begriffe und Zusammenhänge, im Entwurf um die genaue Umsetzung. Wenn die Aufgabe
„vollständig“ oder „mit Datentypen“ sagt, brauchst du die rechte Variante.

:::aufgabe basis 10 1 · Klasse „Fahrzeug“
Zeichne die Klasse **Fahrzeug** für eine Werkstattsoftware:
- private Attribute: Kennzeichen (Text), Kilometerstand (Ganzzahl), Baujahr (Ganzzahl)
- ein statisches, privates Attribut, das zählt, wie viele Fahrzeuge angelegt wurden
- ein öffentlicher Konstruktor mit Kennzeichen und Baujahr
- eine öffentliche Methode, die den Kilometerstand um einen übergebenen Wert erhöht
- eine öffentliche Methode, die das Alter in Jahren zurückgibt

:::checkliste Selbstcheck
- Der Name steht im Singular und oben.
- Alle Typen stehen hinter dem Namen, mit Doppelpunkt.
- Das statische Attribut ist unterstrichen.
- Der Konstruktor hat keinen Rückgabetyp.
:::

:::loesung
```
               Fahrzeug
-----------------------------------------
- kennzeichen : String
- kilometerstand : int
- baujahr : int
- anzahl : int            (unterstrichen)
-----------------------------------------
+ Fahrzeug(kennzeichen : String, baujahr : int)
+ fahren(km : int) : void
+ alter() : int
```
Andere sinnvolle Namen (z. B. `erhoeheKilometer`) sind natürlich auch richtig.
:::
:::

:::aufgabe plus 10 2 · Abstrakt und Interface
Eine Software verwaltet **Medien** in einer Bibliothek. Jedes Medium hat einen Titel und eine Signatur.
Es gibt **Bücher** (mit Seitenzahl) und **DVDs** (mit Laufzeit in Minuten). Ein „Medium“ an sich wird nie angelegt.
Jedes Medium muss die Methode `leihfrist() : int` anbieten, die bei Büchern 28 und bei DVDs 7 Tage liefert.
Außerdem sollen Bücher und DVDs das Interface **Ausleihbar** mit `ausleihen(ausweisNr : String) : boolean`
umsetzen.

Zeichne die Klassen mit Attributen und Methoden. Die Beziehungen zeichnest du als Pfeile – wie im Bild oben.

:::loesung
- `Medium` ist **abstrakt** (Name kursiv), Attribute `- titel : String`, `- signatur : String`, die Methode
  `+ leihfrist() : int` ist ebenfalls abstrakt (kursiv).
- `Buch` mit `- seiten : int` und `+ leihfrist() : int`, `DVD` mit `- laufzeit : int` und `+ leihfrist() : int`.
  Beide erben von `Medium` (durchgezogene Linie, hohles Dreieck an `Medium`).
- `«interface» Ausleihbar` mit `+ ausleihen(ausweisNr : String) : boolean`. Eleganter Weg: `Medium` realisiert
  das Interface (gestrichelte Linie mit hohlem Dreieck an `Ausleihbar`) – dann erben Buch und DVD die Pflicht mit.
  Wenn du Buch und DVD einzeln mit dem Interface verbindest, ist das auch richtig.
:::
:::
