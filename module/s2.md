## 1. Die sieben Beziehungen

Klassen stehen nicht allein. Wie sie zusammenhängen, zeigen Linien mit unterschiedlichen Enden. Das ist **das**
Prüfungsthema schlechthin:

:::screenshot material/s2-beziehungen.svg
Die sieben Beziehungsarten im Klassendiagramm, jeweils mit einem Beispiel aus dem RadWerk-Verleih.
:::

| Beziehung | Bedeutung | Linie | Ende |
| --- | --- | --- | --- |
| Assoziation | „kennt“, „hat zu tun mit“ | durchgezogen | ohne Spitze |
| gerichtete Assoziation | nur eine Seite kennt die andere | durchgezogen | offene Pfeilspitze |
| Aggregation | Teil-Ganzes, Teil kann allein existieren | durchgezogen | **hohle Raute** am Ganzen |
| Komposition | Teil-Ganzes, Teil stirbt mit dem Ganzen | durchgezogen | **gefüllte Raute** am Ganzen |
| Generalisierung | „ist ein“ (Vererbung) | durchgezogen | hohles Dreieck an der Oberklasse |
| Realisierung | Klasse setzt Interface um | gestrichelt | hohles Dreieck am Interface |
| Abhängigkeit | „benutzt kurz“ (z. B. als Parameter) | gestrichelt | offene Pfeilspitze |

### Aggregation oder Komposition?

Frag dich: **Kann das Teil ohne das Ganze existieren – und kann es zu mehreren Ganzen gehören?**

- Ein **Fahrrad** steht an einer **Station**. Wird die Station abgebaut, gibt es das Fahrrad weiter. →
  **Aggregation** (hohle Raute an Station).
- Eine **Rechnungsposition** gehört zu genau einer **Rechnung**. Wird die Rechnung gelöscht, sind auch ihre
  Positionen weg. → **Komposition** (gefüllte Raute an Rechnung).

:::achtung Typischer Fehler: Komposition mit „viele Ganze“
Bei einer Komposition gehört ein Teil zu **höchstens einem** Ganzen. An der Seite des Ganzen steht deshalb nur
`1` oder `0..1` – nie `*` oder `1..*`.
:::

### Generalisierung („ist ein“)

Ein E-Bike **ist ein** Fahrrad. Die Unterklasse erbt alle Attribute und Methoden der Oberklasse und kann eigene
ergänzen oder Methoden überschreiben. Der Pfeil zeigt **von der Unterklasse zur Oberklasse**. In Java heißt das
`extends`, beim Interface `implements`.

:::tipp Eselsbrücke Pfeilrichtung
Das Kind zeigt auf die Mutter: Die Unterklasse „weiß“, von wem sie erbt – die Oberklasse kennt ihre Unterklassen
nicht.
:::

## 2. Multiplizitäten, Rollen, Navigierbarkeit

Eine **Multiplizität** sagt, wie viele Objekte auf einer Seite beteiligt sind. Sie steht **an der Seite, deren
Anzahl sie angibt**.

| Angabe | Bedeutung |
| --- | --- |
| `1` | genau eins |
| `0..1` | keins oder eins |
| `*` oder `0..*` | beliebig viele (auch keins) |
| `1..*` | mindestens eins |
| `2..10` | zwei bis zehn |

:::screenshot material/s2-multiplizitaet.svg
Kunde und Ausleihe mit Multiplizitäten 1 und 0..* sowie dem Assoziationsnamen „tätigt“. Das kleine Dreieck zeigt die Leserichtung.
:::

So liest du die Beziehung in beide Richtungen:
- **Ein** Kunde tätigt **0..\*** Ausleihen.
- **Eine** Ausleihe wird von **genau einem** (1) Kunden getätigt.

Ein **Rollenname** an einem Ende sagt, welche Rolle das Objekt dort spielt. Im Code wird daraus meist der
Attributname. Die **offene Pfeilspitze** zeigt, in welche Richtung man navigieren kann:

:::screenshot material/s2-rollen-navigation.svg
Gerichtete Assoziation von Ausleihe zu Fahrrad mit dem Rollennamen „rad“ und den Multiplizitäten 0..* und 1.
:::

## 3. Das vollständige Beispiel

So sieht das Klassendiagramm für den RadWerk-Verleih aus. Nimm dir zwei Minuten und lies jede Beziehung einmal
laut in beide Richtungen.

:::screenshot material/s2-radwerk.svg
Klassendiagramm des E-Bike-Verleihs RadWerk mit den Klassen Kunde, Ausleihe, Fahrrad (abstrakt) mit EBike und Lastenrad, Station, Rechnung, Rechnungsposition, Interface Zahlungsart mit Kreditkarte und PayPal sowie der Aufzählung RadZustand.
:::

:::loesung So liest man es
- Ein Kunde tätigt 0..\* Ausleihen, jede Ausleihe gehört zu genau einem Kunden.
- Eine Ausleihe bezieht sich auf genau ein Fahrrad; ein Fahrrad kann in 0..\* Ausleihen vorkommen (über die Zeit).
- Ein Fahrrad steht an keiner oder einer Station (0..1 – unterwegs an keiner), an einer Station stehen 0..\* Räder.
  Aggregation: Die Räder gibt es auch ohne die Station.
- Aus einer Ausleihe entsteht keine oder eine Rechnung. Eine Rechnung besteht aus mindestens einer Position
  (Komposition).
- Ein Kunde hinterlegt mindestens eine Zahlungsart. Kreditkarte und PayPal realisieren das Interface.
- EBike und Lastenrad sind Fahrräder und müssen die abstrakte Methode `berechnePreis` umsetzen.
:::

## 4. Vorgehen in der Prüfung

:::schritte
1. Unterstreiche im Text alle **Substantive** – das sind Kandidaten für Klassen und Attribute.
2. Entscheide: Hat das Ding eigene Eigenschaften und Verhalten (→ Klasse) oder ist es nur ein Wert (→ Attribut)?
3. Suche **„ist ein“**-Sätze → Generalisierung.
4. Suche **„besteht aus“, „hat“, „gehört zu“** → Assoziation, Aggregation oder Komposition.
5. Trage für jede Beziehung **beide** Multiplizitäten ein.
6. Ergänze Attribute und Methoden mit Datentypen, wenn verlangt.
:::

:::aufgabe basis 10 1 · Welche Beziehung?
Bestimme jeweils die Beziehung und wo die Raute oder das Dreieck sitzt.
1. Ein Girokonto ist ein Konto.
2. Ein Warenkorb enthält Artikel. Die Artikel gibt es im Shop auch ohne den Warenkorb.
3. Eine Bestellung besteht aus Bestellpositionen, die ohne Bestellung keinen Sinn haben.
4. Ein Lehrer unterrichtet Klassen.
5. Die Klasse `Drucker` setzt das Interface `Druckbar` um.
6. Die Methode `Rechnung.drucke(d : Drucker)` benutzt einen Drucker nur während des Aufrufs.

:::loesung
1. Generalisierung, hohles Dreieck an `Konto`
2. Aggregation, hohle Raute an `Warenkorb`
3. Komposition, gefüllte Raute an `Bestellung`
4. Assoziation (keine Raute, kein Dreieck)
5. Realisierung, gestrichelte Linie, hohles Dreieck an `Druckbar`
6. Abhängigkeit, gestrichelter Pfeil von `Rechnung` zu `Drucker`
:::
:::

:::aufgabe plus 20 2 · Fuhrpark einer Spedition
Zeichne ein Klassendiagramm **ohne Attribute und Methoden**, aber mit allen Multiplizitäten:

Eine **Spedition** besitzt mindestens ein **Fahrzeug**. Fahrzeuge sind entweder **LKW** oder **Transporter**;
ein „Fahrzeug an sich“ gibt es nicht. Jede **Tour** wird mit genau einem Fahrzeug gefahren; ein Fahrzeug fährt im
Lauf der Zeit beliebig viele Touren. Eine Tour besteht aus zwei bis zwanzig **Stopps**, die nur zu dieser Tour
gehören. Jede Tour hat genau einen **Fahrer** als Verantwortlichen; ein Fahrer kann für mehrere Touren eingeteilt
sein. Wird eine Spedition aufgelöst, werden die Fahrzeuge verkauft.

:::checkliste Selbstcheck
- `Fahrzeug` ist abstrakt.
- Zwischen Tour und Stopp steht eine Komposition mit `2..20`.
- Jede Linie hat an beiden Enden eine Multiplizität.
:::

:::loesung
- `Spedition` 1 ◇— 1..\* `Fahrzeug` (**Aggregation**: Die Fahrzeuge werden verkauft, existieren also weiter.
  Eine einfache Assoziation ist auch vertretbar.)
- `LKW` und `Transporter` erben von `Fahrzeug` (hohles Dreieck an `Fahrzeug`); `Fahrzeug` ist abstrakt (kursiv).
- `Tour` 0..\* — 1 `Fahrzeug`
- `Tour` 1 ◆— 2..20 `Stopp` (**Komposition**, gefüllte Raute an `Tour`)
- `Tour` 0..\* — 1 `Fahrer`
:::
:::

Setze diese Klassen sinnvoll in Beziehung und begründe jede Entscheidung in einem Satz:
