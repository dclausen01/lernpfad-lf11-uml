## 1. Die Übersetzungstabelle

In der AP2 bekommst du oft Quelltext (meist Java, C# oder Pseudocode) und sollst daraus ein Klassendiagramm
machen – oder umgekehrt. Mit dieser Tabelle klappt das in beide Richtungen:

| Im Code (Java) | Im Klassendiagramm |
| --- | --- |
| `private int menge;` | Attribut `- menge : int` |
| `protected`, `public`, ohne Modifier | `#`, `+`, `~` |
| `static` | unterstrichen |
| `abstract class` / `abstract` Methode | Name kursiv bzw. `{abstract}` |
| `interface Druckbar` | Klasse mit `«interface»` |
| `class B extends A` | Generalisierung B → A (durchgezogen, hohles Dreieck) |
| `class B implements I` | Realisierung B → I (gestrichelt, hohles Dreieck) |
| `private Kunde kunde;` | Assoziation zur Klasse Kunde, Multiplizität `1` (oder `0..1`, wenn `null` erlaubt ist) |
| `private List<Position> positionen;` | Assoziation zu Position mit `0..*` |
| Objekt wird in der Klasse mit `new` erzeugt und nicht weitergegeben | Hinweis auf Komposition |
| Klasse nur als Parameter oder lokale Variable | Abhängigkeit (gestrichelter Pfeil) |

:::achtung Typischer Fehler: doppelt modelliert
Wenn du eine Beziehung zu `Kunde` zeichnest, schreibst du **nicht zusätzlich** `- kunde : Kunde` in die Klasse.
Entweder Attribut **oder** Linie – die Linie ist im Klassendiagramm die bessere Wahl. Den Attributnamen schreibst
du als **Rollennamen** an das Linienende.
:::

## 2. Vom Code zum Diagramm

Sieh dir diesen Quelltext eines Onlineshops an:

```java
public class Bestellung {
    private int nummer;
    private LocalDate datum;
    private Kunde kunde;
    private List<Position> positionen = new ArrayList<>();

    public Bestellung(int nummer, Kunde kunde) {
        this.nummer = nummer;
        this.kunde = kunde;
        this.datum = LocalDate.now();
    }
    public void hinzufuegen(Artikel artikel, int menge) {
        positionen.add(new Position(artikel, menge));
    }
    public double gesamtpreis() {
        double summe = 0;
        for (Position p : positionen) {
            summe += p.preis();
        }
        return summe;
    }
}

public class Position {
    private int menge;
    private Artikel artikel;

    public Position(Artikel artikel, int menge) {
        this.artikel = artikel;
        this.menge = menge;
    }
    public double preis() {
        return menge * artikel.getPreis();
    }
}

public class Artikel {
    private String bezeichnung;
    private double preis;
    public double getPreis() { return preis; }
}

public class Kunde {
    private String name;
    public String getName() { return name; }
}
```

:::schritte
1. Jede `class` wird ein Rechteck. Einfache Datentypen (`int`, `double`, `String`, `LocalDate`) werden Attribute.
2. `private Kunde kunde` → gerichtete Assoziation von Bestellung zu Kunde, `1` am Kunden, Rollenname `-kunde`.
   Wie viele Bestellungen ein Kunde hat, verrät der Code nicht – `0..*` ist hier eine sinnvolle Annahme.
3. `List<Position>` → „viele“ Positionen. Die Positionen werden **in** `hinzufuegen` mit `new` erzeugt und nie
   herausgegeben → **Komposition** mit gefüllter Raute an Bestellung. Am Anfang ist die Liste leer → `0..*`.
4. `private Artikel artikel` in Position → gerichtete Assoziation mit `1` am Artikel. Der Artikel wird von außen
   übergeben und existiert unabhängig → **keine** Komposition.
5. Die Pfeilspitzen zeigen dorthin, wo das Attribut hinzeigt – Kunde und Artikel kennen ihre Bestellungen nicht.
:::

Klassendiagramm zum Quelltext: Bestellung mit gerichteter Assoziation zu Kunde (Rolle -kunde, Multiplizität 1), Komposition zu Position (Rolle -positionen, 0..*) und Position mit gerichteter Assoziation zu Artikel (Rolle -artikel, Multiplizität 1).
:::

## 3. Vom Diagramm zum Code

Umgekehrt gehst du genauso vor – nur rückwärts durch die Tabelle.

:::aufgabe basis 15 1 · Mitarbeiterverwaltung programmieren
Schreibe das Java-Gerüst (Attribute, Konstruktoren, Methodenköpfe; Methodenrümpfe nur, wo sie sich direkt
ergeben) zu diesem Diagramm:

:::screenshot material/s3-mitarbeiter.svg
Klassendiagramm: Abteilung aggregiert 0..* Mitarbeiter (Rolle -mitarbeiter, navigierbar zu Mitarbeiter). Mitarbeiter ist abstrakt mit statischem Zähler anzahl und abstrakter Methode gehalt(). Festangestellter und Aushilfe erben von Mitarbeiter.
:::

:::checkliste Selbstcheck
- `Mitarbeiter` ist `abstract`, `gehalt()` auch.
- `anzahl` und `getAnzahl()` sind `static`.
- `Abteilung` hat eine Liste von Mitarbeitern – Mitarbeiter kennt seine Abteilung nicht.
- Die Unterklassen rufen im Konstruktor `super(name)` auf.
:::

:::loesung
```java
public class Abteilung {
    private String name;
    private List<Mitarbeiter> mitarbeiter = new ArrayList<>();

    public void hinzufuegen(Mitarbeiter m) {
        mitarbeiter.add(m);
    }
    public double gehaltssumme() {
        double summe = 0;
        for (Mitarbeiter m : mitarbeiter) {
            summe += m.gehalt();
        }
        return summe;
    }
}

public abstract class Mitarbeiter {
    private String name;
    private static int anzahl;

    public Mitarbeiter(String name) {
        this.name = name;
        anzahl++;
    }
    public abstract double gehalt();
    public static int getAnzahl() { return anzahl; }
}

public class Festangestellter extends Mitarbeiter {
    private double monatsgehalt;

    public Festangestellter(String name, double monatsgehalt) {
        super(name);
        this.monatsgehalt = monatsgehalt;
    }
    public double gehalt() { return monatsgehalt; }
}

public class Aushilfe extends Mitarbeiter {
    private int stunden;
    private double stundenlohn;

    public Aushilfe(String name, double stundenlohn) {
        super(name);
        this.stundenlohn = stundenlohn;
    }
    public void erfasseStunden(int h) { stunden += h; }
    public double gehalt() { return stunden * stundenlohn; }
}
```
Die Aggregation ist im Code nicht anders als eine Assoziation: Die Mitarbeiter werden von außen übergeben
(`hinzufuegen(m)`) und existieren auch ohne Abteilung weiter.
:::
:::

:::aufgabe plus 15 2 · Interface im Code finden
Zeichne das Klassendiagramm (mit Attributen, Methoden und Beziehungen) zu diesem Code:

```java
public interface Tarif {
    double berechne(int minuten);
}
public class Minutentarif implements Tarif {
    private double preisProMinute;
    public double berechne(int minuten) { return minuten * preisProMinute; }
}
public class Flatrate implements Tarif {
    private double monatspreis;
    public double berechne(int minuten) { return 0; }
}
public class Vertrag {
    private String vertragsNr;
    private Tarif tarif;
    public Vertrag(String vertragsNr, Tarif tarif) { … }
    public void tarifWechseln(Tarif neu) { this.tarif = neu; }
}
```

:::loesung
- `«interface» Tarif` mit `+ berechne(minuten : int) : double` (Methoden im Interface sind automatisch public).
- `Minutentarif` (`- preisProMinute : double`) und `Flatrate` (`- monatspreis : double`) haben jeweils
  `+ berechne(minuten : int) : double` und **realisieren** `Tarif` (gestrichelte Linie, hohles Dreieck an Tarif).
- `Vertrag` mit `- vertragsNr : String`, `+ Vertrag(vertragsNr : String, tarif : Tarif)`,
  `+ tarifWechseln(neu : Tarif) : void` und einer gerichteten **Assoziation** zu `Tarif` mit Multiplizität `1`
  und Rollenname `-tarif`. Am Vertrag ist `0..*` sinnvoll – ein Tarif kann in vielen Verträgen stecken.
- Keine Komposition: Der Tarif wird von außen übergeben und kann gewechselt werden.
:::
:::
